# Declarative Axum Router And Live LSP Plan

Status: implemented.

## Current Shape

Rust API handlers are declared once and exported by mounting the real handler
on an `ApiRouter` route tree:

```rust
#[typeweld_macros::api(method = "GET", path = "/greetings/{name}")]
pub async fn greet(name: typeweld_axum::Path<String>) -> Result<typeweld_axum::Json<Greeting>, GreetingError> {
    todo!()
}

#[typeweld_macros::api_router]
pub fn routes() -> typeweld_axum::ApiRouter {
    typeweld_axum::ApiRouter::new("server").endpoint(greet)
}

pub fn app() -> axum::Router {
    routes().into_router()
}

pub fn contract() -> typeweld_core::ir::ApiContract {
    typeweld_cli::collect_contract(typeweld_cli::CollectorInput::from_root(
        "@workspace/server-api",
        routes(),
    ))
}
```

`#[api_router]` rewrites `.endpoint(greet)` to hidden descriptor and Axum
adapter calls generated by `#[api]`. User code mounts API handlers with
`.endpoint(handler)`; the route tree is the single publication boundary for
runtime routing and TypeScript contract generation.

## Invariants

1. New user-facing Rust API exports start from `#[api_router]` plus
   `.endpoint(handler)`.
2. User code does not call generated endpoint helper functions.
3. User code does not write separate response wrapper functions for API
   handlers.
4. Contract collection uses `CollectorInput::from_root(package, routes())`.
5. Generated TypeScript remains build output and is not edited by LSP rename.
6. Stale usage data never produces unused endpoint diagnostics.
